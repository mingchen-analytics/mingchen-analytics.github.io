SPORTS DATA ENGINEERING · VALIDATION · IN PROGRESS

NBA Analytics Platform

Raw play-by-play to my own possessions, checked game by game against an independent reference

Every per-100-possession number in basketball depends on judgment calls: when a possession ends, what to do with technical free throws, who gets credit when a substitution happens between free throws. I built a database of every NBA game since 1996-97 in which each of those calls is written down, versioned and tested, and then compared my possession counts with pbpstats, an established public reference, team by team and game by game. This page is about the moment the two stopped agreeing, and why I did not make them agree.

01 — THE CHALLENGE

Every public metric hides a judgment call.

An offensive rebound does not start a new possession. An and-1 free throw belongs to the possession of the basket. A technical free throw belongs to no possession at all. A heave with one second left can distort a lineup's efficiency. Public numbers make these choices silently; here each one is a named rule in a configuration file, with a decision date, worked examples from real games and an automated test. Rules start from a pbpstats_compat profile that copies the reference, so that every later change is a deliberate, documented deviation.

STEP 01raw

Ingest

Raw files are never modified; each one is recorded with its URL, download time and SHA-256. Fixes go in a corrections table.

STEP 02✓ / !

Validate

Hard checks stop a season (unknown player, duplicate key, the same player twice in a lineup). Warnings are reported, never silently fixed.

STEP 03rules

Stints (the ten players on court) and possessions are built from the rules file, keeping the original event order.

STEP 04Δ

Compare

Possession counts are compared with pbpstats per team and game. Every gap is investigated and explained.

02 — THE DROP

Sixteen seasons of agreement, then a cliff.

From 2000-01 to 2015-16 my possession count equals pbpstats' in 97–99% of team-games, and is within one possession in 99.9–100%. From 2016-17 the share of identical counts falls to about 78%, in every season. My code had not changed between those seasons, so something in the data had.

TRY IT · THE RULE BEHIND THE GAP

A possession starts with 2.4 seconds left in the quarter and scores 0 points. Is it an end-of-period heave?

ABOUT 500–560 PER SEASON

The shared rule: a possession that starts with 2 seconds or less left in the period and scores nothing is flagged as a heave and left out of efficiency, because a desperation shot says little about a lineup.

Reveal how each side counts it ↓

pbpstats appears to read it as 2 seconds, so it is a heave. I compare the exact time, 2.4 > 2, so it is not.

Through 2015-16 every possession in the source starts on a whole second, so the two readings never differ. From 2016-17 the clock carries tenths of a second (21,309 fractional possession starts in 2016-17 alone), and about 500–560 scoreless possessions per regular season start with between 2 and 3 seconds left. That single comparison explains most of the drop.

My first explanation was wrong. I initially concluded that pbpstats simply does not count about 515 empty final possessions per season. Comparing whole games side by side showed that pbpstats does have those possessions; my matching method had mislabelled them. I corrected the decision log rather than delete the wrong entry, because the path to an answer is part of the evidence.

03 — THE DECISION

Matching the number was one line away.

Comparing whole seconds instead of the exact time restores the agreement almost completely, and changes nothing before 2016-17. I tested it and kept the exact time. A possession that starts with 2.4 seconds left is a real possession with time to run a play; counting it as a heave would make my data match the reference by making it less accurate. The difference is now a named setting (end_of_period.clock_precision: exact), documented with these numbers, so anyone can switch it and reproduce either result.

05 — DASHBOARD

Every number says where it comes from.

A read-only Streamlit app sits on top of the database. Each figure is labelled as an official NBA.com value, a count from my own play-by-play, or a model result. It runs locally and is not deployed publicly because of the data sources' terms.

What is solid, and what is still open.
